# Домашняя работа №1: Docker и docker-compose

Небольшой сервис заметок на Flask, который хранит данные в PostgreSQL. Приложение и база запускаются одной командой через docker-compose.

## Что внутри

| Файл | Назначение |
|---|---|
| `main.py` | Flask-приложение: `GET /notes` и `POST /notes`, при старте создаёт таблицу `notes` |
| `requirements.txt` | Зависимости: Flask, psycopg2-binary |
| `Dockerfile` | Образ приложения на `python:3.12-slim` |
| `docker-compose.yml` | Два сервиса: `app` (приложение) и `db` (PostgreSQL 16) |

## Запуск

Нужен Docker с плагином compose.

```
docker compose up --build
```

Приложение будет доступно на `http://localhost:5001`. Порт 5001 выбран потому, что на macOS порт 5000 обычно занят AirPlay Receiver. Внутри контейнера приложение слушает 5000, в `docker-compose.yml` проброс `5001:5000`.

Остановить: `Ctrl+C`, затем `docker compose down`.

## Проверка

Добавить заметку:

```
curl -X POST localhost:5001/notes -H "Content-Type: application/json" -d '{"text":"первая заметка"}'
```

Получить все заметки:

```
curl localhost:5001/notes
```

Проверка сохранности данных: выполнить `docker compose down`, затем `docker compose up` и снова запросить `/notes`. Заметки остаются на месте, потому что данные Postgres лежат в именованном volume `pgdata`.

Чтобы удалить данные полностью: `docker compose down -v`.

## Как это устроено

- Приложение подключается к базе по адресу `db:5432`. Внутри сети compose сервисы обращаются друг к другу по имени сервиса.
- Строка подключения передаётся через переменную окружения `DATABASE_URL`.
- У сервиса `db` есть healthcheck (`pg_isready`), а `app` стартует только после того, как база стала `healthy`. Без этого приложение могло бы упасть при старте, пока Postgres ещё запускается.
- В `Dockerfile` зависимости ставятся до копирования кода, поэтому при изменении `main.py` слой с `pip install` берётся из кэша.

## Ограничения

Логин и пароль БД записаны прямо в `docker-compose.yml`, это допустимо только для учебного проекта. Для реального проекта их выносят в `.env`. Flask запущен встроенным dev-сервером, для продакшена нужен WSGI-сервер вроде gunicorn.
